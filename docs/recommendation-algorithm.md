# 素见 · 推荐算法升级方案

> 目标：在现有「兴趣画像 + CES + 新鲜度 + 社交 + 多样性打散」基础上，补齐浏览信号、负反馈、协同过滤与配置化，使首页「为你推荐」更贴合兴趣且可调参。本文件为**方案设计**，落地实现另开任务。

> **设计约束（硬性）**：推荐算法照常运行（画像/协同/负反馈/冷启动都在后台算），但**前端不向用户展示任何"推荐原因"文案**（如"因为你关注过 #xx""看过类似内容的人也在看"等）。推荐结果就是干干净净的内容流，用户无感知、无解释、无打扰。代码层不生成、不返回 reason 类字段。

---

## 0. 现状盘点（已具备的能力）

代码位置：`internal/store/store.go` 的 `RecommendForUser` / `interestTags` / `diversify`，以及
`internal/handler/content.go` 的 `feed`。

| 能力 | 现状 | 说明 |
|------|------|------|
| 兴趣画像 | ✅ | 点赞×3 / 收藏×4 / 评论×2 / 自己发布×2 / 关注作者×2 的标签加权画像 |
| CES 互动分 | ✅ | 点赞×1 + 收藏×1 + 评论×4，带饱和归一 `(x)/(x+5)` |
| 新鲜度衰减 | ✅ | 30 天半衰期 `1/(1+age/30)` |
| 社交关系 | ✅ | 已关注作者 +5 加权 |
| 多样性打散 | ✅ | `diversify` 单标签上限 3 篇，不足放宽补齐 |
| 冷启动退化 | ✅ | 无互动历史时退化为热度+新鲜度 |

**结论**：算法骨架已覆盖主要维度，基础可用。本次升级聚焦"补齐信号维度 + 纠偏 + 可运营"。

---

## 1. 核心缺口（本次要补的）

1. **浏览行为未进画像** —— 已有 `ViewHist`（浏览历史）数据，但 `interestTags` 完全没用。用户"点进去看"是比"点赞"更轻但量更大的兴趣信号。
2. **没有负反馈** —— 用户刷到不想要的，只能划走，系统学不到"别再推这个"。缺"不感兴趣/减少此类"。
3. **没有协同过滤** —— 只会"我喜欢的标签"，不会"和我相似的人也喜欢"。Item-CF 能以很低成本补上。
4. **冷启动太粗** —— 新用户直接退化为全局热度，没有"注册时选兴趣"或"前 N 篇强插多样内容"的引导。
5. **权重写死** —— `score` 各项系数（tagScore×1、cesNorm×5、rec×3、followBonus）硬编码，运营无法调参、无法做 A/B。

## 2. 升级方案（五大块）

### 2.1 浏览/点击信号并入画像（成本低）
- `interestTags` 增加_read_ 分支：遍历 `ViewHist[userID]`，对浏览过的笔记标签加权重（建议 **×1**，低于点赞但高于无）。
- 浏览去重仍在 `IncViewsDedup`（30 分钟/用户/笔记），避免同一篇反复刷爆权重。
- 浏览历史已落盘 `view_history.json`，**无需新增存储**，只改打分逻辑。

### 2.2 负反馈机制（纠偏核心）
新增数据（存 `data/feedback.json`）：
```json
{ "userID": "u1", "noteID": "n2", "type": "dislike", "tags": ["美食","旅游"], "ts": 1234567890 }
```
- 前端卡片加「…」菜单 → "不感兴趣" → 记一条 `dislike`，同时把该笔记**标签权重在该用户画像里打折**（如 ×0.3，或直接扣减）。
- `RecommendForUser` 命中 `dislike` 笔记直接剔除；对命中 `dislike` 标签的候选做降权。
- 同一用户对同标签多次 dislike 累计，画像里该标签权重趋近 0，该类内容在推荐中逐渐减少。

### 2.3 Item-CF 协同过滤（补"相似人"维度）
- 离线（每次请求前或定时）构建**共现矩阵**：基于 `Likes`/`Favs`/`ViewHist` 算笔记两两相似度（Jaccard of 互动用户集合，或余弦）。
- 对该用户近期高互动笔记集合 `Seed`，取相似度最高的 Top-K 候选作为"协同分" `cfScore`。
- 合并进主分数：`score += cfScore * W_cf`（W_cf 默认 2，可配）。
- **规模控制**：当前为 JSON 文件存储、用户量级小（校内/社区），共现矩阵内存计算即可，无需引入向量库。若未来用户过万再考虑离线批算。

### 2.4 冷启动精细化
- **注册引导**：新用户注册后弹"选择感兴趣的话题"（复用现有 tags 体系），写入初始轻量画像（等价于 `interestTags` 预置）。
- **新用户前 10 篇**：强制 `diversify(maxPerTag=1)` + 插入 2~3 篇跨类目"探索内容"，快速收集信号。
- 判定冷启动：画像总权重 < 阈值 或 注册 < 3 天 且 互动 < 5 次。

### 2.5 权重可配置 + 轻量 A/B
- 把打分系数抽到 `data/reco_config.json`（默认值保持现状）：
  ```json
  { "w_tag": 1.0, "w_ces": 5.0, "w_rec": 3.0, "w_follow": 5.0, "w_cf": 2.0,
    "w_view": 1.0, "dislike_decay": 0.3, "max_per_tag": 3, "cold_start_days": 3 }
  ```
- 启动时读入，运行时改文件 + 重启生效（沿用项目"相对路径 + JSON 配置"风格）。
- A/B：按 `userID` 哈希分桶，桶 B 用另一组系数，后台统计两桶的点击率/停留，验证调参效果。

## 3. 分数公式（升级后）

```
score(n, u) =
    w_tag   * Σ prof[u][t]            // 兴趣画像（含浏览信号）
  + w_ces   * cesNorm(n)              // 互动热度（饱和）
  + w_rec   * recency(n)              // 新鲜度
  + w_follow* followBonus(n,u)        // 社交
  + w_cf    * cfScore(n, u)           // 协同过滤
  - Σ dislikePenalty(n,u)             // 负反馈惩罚
```

然后过 `diversify(maxPerTag)` 多样性打散，冷启动走 2.4 特殊分支。

## 5. 验收标准（建议）

1. 浏览过的标签，后续推荐该标签内容占比上升（可量化对比）。
2. 点"不感兴趣"后，该笔记及同类标签在推荐中明显减少或消失。
3. 新注册用户（无历史）前几屏内容多样、跨类目，而非单一全局热度。
4. 改 `reco_config.json` 系数并重启，推荐排序可见变化（运营可调参）。
5. 黑标仍绝不进推荐（现有约束不变）。
6. 全量 `go test ./...` 通过；JSON 存储无并发写冲突（沿用 `sync.Mutex`）。

## 6. 实施建议顺序

1. **阶段一（信号补全，改动最小）**：2.1 浏览进画像。纯算法内改动，无新存储、无前端大改。
2. **阶段二（纠偏）**：2.2 负反馈（需新 `feedback.json` + 前端菜单）。
3. **阶段三（协同过滤）**：2.3 Item-CF 协同过滤。
4. **阶段四（体验与运营）**：2.4 冷启动引导 + 2.5 配置化/A-B。

> 备注：现有引擎已能跑，建议先落地阶段一+二（改动小、效果直观），再视数据决定是否上协同过滤。
