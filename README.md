# 素见 (Sujian)

局域网内可访问的「小红书」风格内容社区。支持图文笔记与视频笔记、发布/点赞/收藏/评论/关注/搜索，  
注册需管理员审核后方可登录。界面基于 **源力设计系统**（`colors_and_type.css` + `components.css`）构建，  
使用 Go 标准库实现，**单二进制、零外部依赖、零数据库**，双击即可运行。

> 📖 **完整使用手册**（纯使用说明，含注册/发布/社交/管理后台/FAQ，从头重写版）：[`docs/usage.md`](docs/usage.md)（旧版保留：[`docs/user-guide.md`](docs/user-guide.md)）

## 快速开始

从 GitHub 克隆或下载源码后，进入项目根目录（`sujian`）：

```bash
git clone <仓库地址> sujian
cd sujian
```

项目文件直接放在当前文件夹（sujian）根目录下，进入后执行：

```bash
./start.sh              # 启动：自动编译 + 后台常驻
./start.sh stop         # 停止
./start.sh restart      # 重启
./start.sh status       # 查看运行状态
```

启动后控制台会打印访问地址：

```
素见已启动 ✓
  本机:   http://localhost:8099
  局域网: http://192.168.x.x:8099      ← 同一 WiFi/网线下的手机、电脑用这个打开
  日志:   data/sujian.log  （停止: ./start.sh stop）
```

- 服务在**后台常驻**运行，关闭终端也不影响；日志写入 `data/sujian.log`
- 端口被占用时：`PORT=9000 ./start.sh`
- 管理员初始密码可在 `main.go` 顶部的 `AdminPass` 修改。

### 想先看效果？一键生成演示数据

```bash
go run ./cmd/seed      # 已有数据时跳过
go run ./cmd/seed -f   # 强制清空 data/ 与 uploads/ 后重建
```

生成 3 个演示用户（密码均为 `demo123`：苏小厨/阿梨/数码君）+ 7 篇各频道笔记（自动生成的渐变封面图，含绿/黄/红三种等级演示）+ 评论/点赞/收藏/关注关系，首屏立刻有内容。

**核心约定**

- **不同用户存不同文件夹**：上传的图片/视频统一放 `uploads/<用户ID>/`，数据库中只存相对路径，`/uploads/` 由服务器静态托管。
- **数据落盘**：每次写操作原子写 JSON（先写 `.tmp` 再 rename），重启不丢数据。
- **会话**：登录后签发随机 Token 存 Cookie（HttpOnly），服务端内存维护，重启后需重新登录。

## 管理员与审核流程

1. 首次启动自动创建管理员 `admin / admin123`（可在 main.go 修改）。
2. 新用户注册 → 状态 `pending` → 提示"等待管理员审核"。
3. 管理员登录后进入 `/admin` → 「用户审核」→ 通过/拒绝。
4. 通过后用户即可登录、发布笔记。
5. 新发布的笔记进入**待审核**，管理员在 `/admin` → 「内容审核」用红黄绿三色定级：
   - **绿**：首页推送 + 自由浏览
   - **黄**：一般内容，首页正常展示
   - **红**：敏感内容，首页/搜索/主页均展示，封面模糊 + 进详情需确认，未登录不可见
   - 也可直接**驳回**（作者会收到通知）；已通过的可随时**改级**或**下架**
6. **批量创建用户**：`/admin` → 「用户管理」→ 文本框每行 `用户名 密码 昵称`，勾选「官方认证」即可统一设定官方认证标识（创建即 active 可用）。

## 上传限制（可在 main.go 修改）

- 图片：jpg / jpeg / png / gif / webp，单个 ≤ 10MB；上传时**自动优化**：长边 > 1600px 等比缩放，不透明图转 **JPEG(q82)**（含透明通道保留 PNG），WebP / GIF（动图）原样保留——从源头控制存储占用
- 视频：mp4 / webm / mov / m4v，单个 ≤ 200MB；**有 ffmpeg 时自动转码压缩**（统一转 H.264+AAC 的 720p mp4，crf28，实测约省 80%+ 体积；≤30MB 才转码避免阻塞发布；无 ffmpeg 或转码失败时原样保存）
- **安全加固**：图片读取有内存上限（防超大请求体撑爆内存）、回退原样保存前校验文件头 magic bytes（挡掉伪装成图片的 HTML/脚本）

## 备注

- 密码使用 salt+SHA256 存储（标准库实现，保证任意环境离线可编译；局域网内使用强度足够）。
- 纯 Go 标准库（`net/http` + `encoding/json`），无 cgo、无第三方包，`go build` 一次编译到处跑。
- **自动化测试**：`scripts/test.py`（项目内置回归脚本，不再依赖 /tmp），覆盖账号/审核/内容/通知/好友/举报/私信/内容治理等全链路，当前 **全部断言 ALL PASS**。运行：清空 `data/` 后启动服务，执行 `python3 scripts/test.py`。
- **单元/并发测试**：`go test ./...`（纯进程内 `httptest`，驱动真实 handler + 真实 store，不依赖网络）；`go test -race ./...` 额外验证并发安全。关键用例：`TestFunctionalFlows`（注册待审→管理员通过→发笔记→审核→评论点赞→私信无密码泄露→举报→被禁内容自动下架）、`TestConcurrentHandlerLoad`（高并发读写下 `-race` 无竞态）、store 层 `TestConcurrentAccess`、`image_opt_test.go`（图片优化 + 上传安全：`TestUploadOptimizesImage` 上传大图自动压缩、`TestUploadRejectsOversizeImage` 超大伪图片被拒、`TestUploadRejectsDisguisedFile` 伪装成图片的 HTML 被拒）。所有测试 ALL PASS，gofmt/go vet 干净。
- **数据可靠性**：浏览量采用节流落盘（累计 20 次变更或 30 秒落盘一次），收到 `SIGINT/SIGTERM`（Ctrl+C / `./start.sh stop`）时自动全量落盘后退出，不丢数据。
- **下架笔记生命周期**：下架（软删除）后保留 30 天宽限期，期间可在管理后台恢复或永久删除；超期可由管理员在管理后台一键清理（`清理旧下架` 按钮，默认 30 天，可自定义天数）。永久删除会一并清理 likes/favs/comments/通知与媒体文件，不可恢复。
- **瀑布流**：首页/搜索/标签/主页采用 **JS 真瀑布流**（`public/js/masonry.js`，方案见 [`docs/masonry-plan.md`](docs/masonry-plan.md)，已实现）：卡片按时间倒序落入当前**最短列**，图片 `onload`/`error` 与窗口 `resize` 触发自动重排，响应式 **4/2/1 列**（≥900px / 480~900px / <480px），加载更多也自动找最短列，彻底解决原 CSS 多列布局的空隙、落点不可控、删除留窟窿等问题；零第三方依赖。
- **存储优化**：图片上传自动压缩（见「上传限制」）；**视频上传自动转码压缩**（有 ffmpeg 时，720p H.264/AAC，实测省 80%+）；`data/*.json` 以**紧凑 JSON**（无缩进）落盘，比格式化写法省约 16~30% 体积，且保持原子写（临时文件 + rename）；**按需落盘**——写操作只序列化保存发生变更的数据文件（点赞只写 likes.json），避免每次小操作全量重写 13 个文件，数据量增大时写入仍保持低延迟（进程退出时全量兜底保存，不丢数据）。
- **性能参考**（实测：1000 篇笔记、10 核 Mac、500 并发）：读接口单请求 0.6~1.5ms；信息流 ~6.6k QPS、笔记详情 ~10k QPS、搜索 ~10k QPS、静态页 ~37.5k QPS、发评论 ~17.9k QPS；模拟 500 台设备同时打开应用（1500 请求）0.2s 完成、零失败；500 并发时内存峰值 ~120MB（常驻 20~30MB）。自带压测脚本：`scripts/bench.js`（`CONC=500 node scripts/bench.js`，写路径需 `NOTE_ID=n_xxx`）。

## 并发安全（实现要点）

- 数据层 `Store` 用 `sync.RWMutex` 保护；**所有「返回内部对象/切片」的读查询均在持锁期间制作拷贝**返回，handler 在锁外持有的是独立副本，杜绝读-写 data race。
- 写操作（新建笔记/评论/私信/通知等）在**写锁内完成内存修改 + `saveLocked()` 落盘**后再释放锁，避免多请求交错时旧快照覆盖新数据导致丢失。
- 落盘采用临时文件 + 原子 `rename`，保证崩溃时数据文件不半写。
